## Findings (root causes, read from code)
- Bug root cause: `K8sService.getClusters()` (electron/k8s.ts ~541) returns `this.kc.getContexts()` from a cached `KubeConfig`. `this.kc` is only re-read from disk in `reloadKubeConfig()`, which runs on a context switch (`setContextWithSmartReload`), after 10 minutes, or on a 401 retry. A new context in the file is invisible until one of those happens. The renderer also fetches the list only once on mount (App.tsx `clustersList`, used by StatusBar) and when SecondarySidebar `mode` becomes 'clusters'. `K8sService.hasContext()` (used by terminal creation in main.ts ~2263) has the same stale-cache problem.
- `settings_kubeconfigPath` is stored (main.ts `settings:setKubeconfigPath`) but NEVER honored: K8sService always calls `loadFromDefault()` (KUBECONFIG env, else ~/.kube/config). Only the pod worker message type accepts `kubeconfigPath`, and main never sends it. Decision: honor it now (single source of file resolution), falling back to default when the path is empty or does not exist, with `~` expansion.
- Active watchers in K8sService are singletons per kind (`activeWatchers` keyed 'pods', 'deployments', 'nodes', `generic:<type>`), and their reconnect closures capture the old `contextName`. After a rename of the active context they would reconnect with a name that no longer exists, so they must be stopped (`stopAllWatchers()`); the renderer restarts them because `Dashboard` receives the new `clusterName`.
- Terminals bound to a context use a per-terminal override kubeconfig with `current-context: <old>` (electron/terminal.ts `writeContextKubeconfig`); it must be rewritten on rename.
- Only `pinnedClusters` in electron-store is keyed by context name (checked all `store.get/set` calls). Renderer keyed state: `selectedCluster`, `attemptedCluster`, `viewTabsByClusterRef`, `editorTabsByClusterRef`, `panelTabs[].clusterContext` and `.execContext.context`.
- Baseline: `npx tsc --noEmit` is clean. `npm run lint` is already broken repo-wide (~1600 pre-existing problems), so lint only the files you touched (`npx eslint <files>`) and make sure you add no new errors.
- `onWindowFocused` in preload uses `removeAllListeners`, so do NOT use it for the focus refresh (it would kill Dashboard's listener). Use the DOM `window` `focus` event in the renderer.
- Toast container in App.tsx is `z-[100]`, below modals (`z-[200]`); raise it to `z-[300]` so rename errors are visible over the modal.

## Design decisions
1. Watch with `fs.watchFile` (stat polling by path, interval 1000ms, `persistent:false`), following electron/aws.ts. Path polling is immune to editors that replace the file via atomic rename (inode change), and works when the file appears later. Debounce 400ms, then compare a SHA-1 of the file contents against the last-seen hash, so touches and our own writes are ignored.
2. Self-write suppression: after the rename writes the file, K8sService reloads synchronously (updating its stored hash) and does NOT emit the event; the renderer gets the new list from the rename IPC result. Later watcher ticks see an identical hash and do nothing.
3. Refresh swaps `this.kc` for a freshly loaded `KubeConfig` but re-applies the in-memory active context (`this.currentContext`) to it, so API calls in flight and connected-cluster watchers are undisturbed. Watchers are stopped only if the ACTIVE context was removed (then the renderer toasts and returns to the cluster list). A parse error mid-edit keeps the old config (never blank the list).
4. `getClusters()` and `hasContext()` (on miss) call the cheap hash check first, so even a missed watcher event self-heals on the next list fetch.
5. Event: `k8s:contextsChanged` with payload `{ contexts, added, removed }`, emitted only when the context list signature (name+cluster+user+namespace) changes. Preload `onContextsChanged(cb)` returns an unsubscribe using `ipcRenderer.off` for its own listener only.
6. Rename IPC returns a discriminated result `{ ok:true, newName, clusters, pinnedClusters } | { ok:false, error }` (avoids Electron's "Error invoking remote method" prefix). Channel `k8s:renameContext`, validated with zod via `safeHandle`; preload `window.k8s.renameCluster(oldName, newName)`.
7. File mutation: parse each kubeconfig file with js-yaml, rename in every file that defines the old context, update `current-context` in every file where it equals the old name, dump with `lineWidth:-1, noRefs:true`, write to a temp file in the same directory with the original mode, fsync, rename over the target (resolve symlinks first). Keep a one-file backup `<file>.lumen.bak` (mode preserved). Abort if the file content changed on disk between read and write. Comments/ordering may be lost; no data is dropped.
8. Not blocked by Safe Mode (it edits a local file, not a cluster); log it with `getAuditLogger().log(...)` category 'MUTATE'.
9. Shared types in a new `src/types/cluster-context.ts` (imported by preload and both d.ts files). The cluster list moves into a `useClusterContexts` hook in App so StatusBar, SecondarySidebar and the title bar share one list.
