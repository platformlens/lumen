# Implementation Plan

## Investigation and layout decision

The definite viewport chain is already present from `src/App.tsx` (`h-screen min-h-0` and nested `h-full`/`flex-1 min-h-0` wrappers) through `src/components/Dashboard.tsx` (`h-full` root and `flex-1 min-h-0 overflow-y-auto` content scroller). The regression is localized to `src/components/dashboard/views/NodesView.tsx`: its root is only `min-h-full`, which does not give the table flex track a definite available height, while its current table region is forced to `h-[400px] min-h-[400px] flex-none`, so the table can render but can never respond to window height.

Use the existing CSS flex chain rather than adding a height `ResizeObserver`. A definite `h-full` Nodes root can distribute the Dashboard scrollport height to a `flex-1` table region immediately on every browser/Electron resize; retaining `min-h-[400px]` clamps the table to a usable concrete viewport when expanded stats consume the available height, and the root's default visible overflow lets that minimum-height table extend the Dashboard scroller's scrollable area. This avoids resize state, observer cleanup, render churn, and duplicated layout arithmetic; keep the existing width-only `ResizeObserver` unchanged.
