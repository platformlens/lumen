# Implementation Plan

## Investigation and layout decision

The definite-height chain is intact from `App.tsx` (`h-screen`) through the flex/overflow wrappers to `Dashboard.tsx` (`h-full`) and its content scroller (`flex-1 min-h-0 overflow-y-auto`). The chain becomes indefinite inside `NodesView.tsx`: the Nodes root was changed from `h-full overflow-hidden` to `min-h-full`, and its table region was changed from a zero-minimum flex region containing a `min-h-[400px]` viewport to a region that itself has only `min-h-[400px]`. Neither `min-h-full` nor `min-h-[400px]` establishes the definite containing-block height required by the nested container's `h-full` and `TableVirtuoso`'s `height: '100%'`, so the virtualizer can resolve without a usable viewport and appear missing.

Use a fixed 400px table viewport as the sizing boundary. This is preferable to restoring `h-full overflow-hidden` on the Nodes root because a fixed, non-shrinking table contributes to the page's intrinsic scroll height: expanded stats can make the outer Dashboard scroller taller, while the reached table still has its own definite viewport and internal virtualization scroll. Keep `Dashboard.tsx`'s `min-h-0` page-scroller change and keep the architecture aggregation/chart logic unchanged.
